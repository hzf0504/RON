## 当前交付

- `src/Assistant`：.NET 8 Windows Forms 独立助手，0.2.0-experimental，普通权限运行。
- `native/probe.cpp`：x64 进程内 EOS 网卡候选筛选和观测，普通/延迟导入表挂接；不覆盖游戏、Steam、EOS 或现有 DLC 补丁。
- `SessionJournal.cs`：UTC/单调时钟/会话编号、测试角色、操作与异常日志、轮换、手动标记。
- `DiagnosticBundle.cs`：当前/历史会话白名单打包、地址与路径脱敏、文件哈希清单、损坏尾行计数；不上传。
- `scripts/build.ps1 -SelfContained` / `package.ps1`：可复现构建和便携分发，包含运行时及其许可文件；不携带个人会话、游戏文件或补丁。
- `README.md` / `TESTER_GUIDE.md` / `LOG_FORMAT.md`：使用、分发、未来双机验收及日志解释。

2. 用户要求停止本机联网测试**之前**，本机曾通过 Steam 启动游戏，创建仅好友大厅（未邀请他人，未形成双机对局）。旧观测会话：`dist/RonWgAssistant/sessions/20261101-093922-92b375`。
3. 旧会话识别实际 EOS `1.19.1.2-53289219`；观测到 70 次 SDK 网卡枚举及公网 UDP 端点。最后记录导入表恢复 7/7；游戏已退出。`files-after.json` 核对原文件未变。当时 WG 未启用，存在其他 TUN，不能把这个场景当作用户正常游戏的故障现场。
4. 旧会话没有远端玩家成功收发，因此不能确认官方邀请的实际对局路径。候选过滤在合成 SDK 中生效，仅证明拦截实现，不能证明实际 RON 选用了 WG。

## 后续开发顺序

优先分析测试者回传的同编号房主/客机日志：先确认 SDK 候选视图和 P2P API 活跃情况，再匹配 EOS UDP 端点、接口预测与必要的接口捕获。若只看到官方公网/中继回退，记录此证据，再决定是否研究进一步传输模块；不要预先替换 SDK/Steam DLL 或改写 EOS 消息语义。

当前方案不改 EOS 包的可靠/不可靠语义，不改账号/大厅/邀请，不强制 NoRelays。恢复通过还原导入表并重启游戏清除缓存；助手异常失去心跳约 5 秒后模块自动停止。真实 SDK/游戏版本更新后先调查，不能直接更新 compatibility.json 来绕过门槛。

喵服已改用自有 `nya-client`；保留工作区交接文件中对此客户端的更新。网卡仍描述为 WireGuard Tunnel，默认名 nya。不要读取客户端配置、密钥、令牌或私有 API。

## 2026-11-07 延迟记录实现

0.3 增加独立的 `RonLatency.dll`。对已锁定哈希的本机游戏构建，静态定位到 `APlayerState::UpdatePing` 方法 RVA `0x331C140`、虚表槽位 RVA `0x6DA26D8` 和 `0x743B5F8`。从反射元数据核对 Role、PlayerId、PlayerNamePrivate，回调记录引擎传入的秒数并换算为 ms。此方法在原函数中执行 1.1 秒上限处理和多秒求平均，回调保存的是原始传入参数。

助手启动后自动跟随游戏进程建立和结束独立延迟会话。房主按每条客机连接显示，客机显示自己与房主的连接。每个有效引擎更新写入顺序日志段，界面按秒显示均值、范围和峰值，可选择历史会话或导出脱敏 ZIP。缺失、无效和过期数据分别显式呈现。采集模块的心跳恢复独立于旧 WG 适配模块。

离线验证覆盖原函数参数传递、分玩家原始样本、超过引擎上限的尖峰、停止恢复、失联恢复、同进程重启、分段和尾行读取、玩家名称脱敏，以及真实 WinForms 消息循环中的历史选择和窄窗口。具体结果以 `tests/results` 中本次验证目录为准。

当前限制是尚未在真实多人对局中验证此入口的调用、玩家归属和更新频率，不能将离线夹具截图或样本计入实际游戏测量。
